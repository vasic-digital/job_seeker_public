## Soak harness: `cmd/jssoak` (engine `eligibility.Soak`)

Dry run only: it scores and compares; it approves, drafts and sends nothing and writes no posting back. The score-time shadow
(`ScorePosting`) and the approve-time shadow (`HardGates`) both run over every posting under each overlay class (nil, empty,
present-no-data, plus the operator's real overlay with `-overlay DIR`). Pass criterion: `shadow_permissive`, `shadow_stricter` and
`shadow_rule_divergent` all 0 (also no panic, no changed outcome) over at least `-min-sample` posting rows (rows flagged `dup_of` are not removed) (default 200).
Fewer postings, none, or any refused provider is exit 2, never a pass. Gates that never fired on the sample are printed as
UNEXERCISED: parity for them is not shown by that sample.

Two real-traffic sources:

1. `-replay-db FILE`: reads the postings of an existing evidence database read-only. Bodies of the 2026-11-24 `jsobserve` run are sealed
   under that run's ephemeral key and are not readable, so a replay scores on title and structured fields only.
2. `-live -dir DIR`: fetches now through the real adapters, the persisted limiter, the egress allow-list and the compliance guard (robots
   and `provider_tos`), then scores with bodies. A provider is fetched only after the operator names it in `-accept-terms`; the tool never
   accepts terms itself.

### Gate and how to run longer soaks

`bash gates/verify_shadow_soak.sh` (env `JS_SOAK_DB`, `JS_SOAK_MIN`) runs the replay; `--prove-failure` shows control rc 0, a dropped
`junior_or_intern` rule rc 1, a minimum above the sample rc 2. It is host-dependent (the observer database is outside the repository), so
on a host without it the gate is rc 2.

A longer live soak (operator action, because each provider's current terms must be reviewed and accepted first):

```bash
go build -o /tmp/jssoak ./cmd/jssoak
/tmp/jssoak -live -dir $HOME/.local/share/job_seeker-soak/run1 -providers remoteok,hackernews,arbeitnow,jobicy \
  -accept-terms remoteok,hackernews,arbeitnow,jobicy -cycles 8 -every 61m -min-sample 500 -overlay <career_private dir>
```

Rounds inside a provider's interval fetch nothing (the persisted limiter); `-every` should be at least the slowest interval. Remotive is
refused by its robots.txt (`docs/operator/provider-compliance-2026-11-24.md`) and must not be listed. The same `-dir` can be reused: the
limiter state is in its database.

## SC-032: policy scope matrix (`jsctl policy matrix`, `gates/verify_scope_matrix.sh`)

Before: `Policy.Check` resolved only the scopes the policy file declares, and the shipped policy declares none (one scope), and the matrix
unit test used a synthetic catalogue. Now `Policy.CheckMatrix` clones the policy with a scope layer for EVERY provider name, every ATS and
every country code AA..ZZ that tries to switch every locked gate off, then resolves the complete cartesian product, including "no scope"
per dimension, through the real `Resolve`. On the shipped catalogue and policy (`evidence/JSK-T244/sc032-matrix.txt`):
12 providers x 4 ATS x 676 countries, each plus no-scope = **44005 scopes resolved, 4 locked gates stayed on**, rc 0. The gate's
`--prove-failure`: a locked gate off by default is rc 1, a policy that declares no locked gate is rc 2 (vacuous), control rc 0 with the
evidence line. RED first: `evidence/JSK-T244/sc032-red.txt`.

Honest boundary: a policy file can name only the three provider scopes in `Catalog.Providers` (remotive, remoteok, himalayas); the matrix
uses all 12 shipped names so a scope added later is already covered. The operator layer may switch a locked gate off by design and is not
part of this criterion.
